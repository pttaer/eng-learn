# Project rules

## UI spacing & layout consistency
- Canonical Specification: Strictly follow [`docs/TYPOGRAPHY_SPACING_RULES.md`](file:///e:/Eng/docs/TYPOGRAPHY_SPACING_RULES.md) and [`.agents/rules/canonical-spacing.md`](file:///e:/Eng/.agents/rules/canonical-spacing.md).
- Reference Exemplar (Gold Standard): The IELTS Academic Writing Hub view (`Mobile/1.0.0/37-mobile-ielts-writing.png`) defines the canonical padding & spacing rule for all views across the app: 24px screen/workspace inset with flush-left alignment, 16px all-around card padding with 12px border radius, 8px internal card gap, 8px-12px button gaps with 10px radius (`--radius-btn`), and 12px-20px section/block rhythms.
- Typography Hierarchy: Use semantic tokens (`--font-h1`, `--font-h2`, `--font-h3`, `--font-h4`, `--font-kicker`, `--font-body`, `--font-prompt`). Never use arbitrary pixel sizes like 19px, 21px, etc.
- Spacing Scale: Follow the 4px/8px rhythm (`--gap-section`: 32/16px, `--gap-block`: 20/12px, `--gap-group`: 12/8px, `--gap-element`: 8/6px). No ad-hoc margins that stack on top of a parent `gap`.
- Padding Tiers: Use `--pad-screen`, `--pad-workspace`, `--pad-card`, `--pad-card-compact`, `--pad-modal`, `--pad-btn`.
- Mobile-first: write base styles for mobile. One breakpoint boundary: `max-width: 768px` for mobile, `(width > 768px)` for desktop. 360px only for small-phone tweaks. Do not add new 600/640/760/800/820/840/900 queries.
- Mobile Safe Clearance: Views under the fixed mobile bottom nav (≤768px) keep `--safe-bottom-dock: 84px` plus `env(safe-area-inset-bottom)`. Above 768px it is 0. IELTS has no bottom nav and uses `--pad-workspace`.
- Touch Targets: All interactive buttons, chips, and pills must be at least 44px (`--touch-target-min`) on every touch device, with horizontal side-by-side flex docks. Only fine-pointer desktops (`(hover: hover) and (pointer: fine)`) may use 36px.
- Text floor: smallest text is `--font-kicker` (11px). Mobile inputs, selects and textareas use `max(16px, var(--font-body))` to stop iOS zoom.
- All dossier views share one skeleton: toolbars span the 1040 workspace; card and nav bar share one centered column (card width, 760) so edges line up; every view starts at the same top edge.
- Never let a slot be smaller than its content (no `contain: size` on content slots); siblings must not overlap.
- Check padding, gaps and alignment on every view, not just the one being edited. Awkward or inconsistent spacing is a bug.
- Two typefaces max: `--font-sans` for reading and UI, `--font-mono` for telemetry, kickers, CEFR levels, timers, indices and keycaps.
- Anti-patterns (see spec §11): no vertical stacking of horizontal tabs on mobile; no crushed tables (wrap in horizontal scroll, `min-width: 600px`, `white-space: nowrap`); no corner compass or watermark over the mobile bottom nav; rating buttons stay in one row; no double outlines / concentric borders (never place a stroked box or card inside another bordered surface; use pure tonal elevation with zero inner border); no decorative diamond stars (`✦`) or black filled stars (`★`) on titles or kickers (clean text or white 5-star `☆` only); no redundant bottom action buttons in grid tiles (Card-as-Button with unbordered `44×44px` top-right arrow affordance).
- Apple-Calm & Sensory UI: use continuous curvature tokens (`--radius-squircle-sm: 10px`, `--radius-squircle-md: 16px`, `--radius-squircle-lg: 24px`, `--radius-pill: 9999px`), spring presses (`scale(0.975)`), gentle mistake shakes (`@keyframes apple-shake`), procedural acoustic haptics (`acoustic-haptics.ts`), and 4-second Universal Undo toasts (`undo-manager.ts`).
- Defensive Input Normalisation: sanitize smart quotes (`’‘` -> `'`, `“”` -> `"`) and strip trailing punctuation in exercise engines so autocorrect never causes false negatives.
- After any layout/CSS change, measure sibling gaps and widths on all routes at desktop (1440) and phone (390) widths, then screenshot and look at them before calling it done.
- Kickers: `--font-kicker` (11px) with `--font-kicker-spacing` (0.08em), no inline overrides. One rule per class; a duplicate silently overrides tokens.
- Badges and chips stay on one line. A row holding a kicker plus a badge wraps with `gap: 4px 8px`.
- Alignment is flush-left. Centre only a whole hero or empty-state card. Clean typography with no `✦` or `★` ornaments.
- No 0–4px gaps between stacked text blocks on mobile: element 6px, group 8px, block 12px, section 16px. Exempt: a heading with its own one-line subtitle, and table rows.
- No fixed-height nested scroll box for a content list on mobile; the page scrolls (canvas and map views exempt).
- Full-width CTA labels wrap inside the button; they never overflow.
- Every clickable (`button`, `a[href]`, `[role=button]`, `[role=tab]`, `[data-route]`) is at least 44×44 on phones. Inline prose links are exempt.
- Mobile titles and labels wrap. No `text-overflow: ellipsis` on them.
- Canonical Z-Index, Contrast & Skeleton Shimmer: bind all layer stacking to tokens (`--z-sunk` through `--z-cursor`); use WCAG 2.2 AAA status contrast pairs (`--ink-good`, `--ink-on-good`, etc.); use `.skeleton-box` with `--shimmer-base` and `--shimmer-highlight` for async views.
- Card-as-Button Grid & Hero Balancing (spec §12): in mobile card decks, make the full card clickable with an unbordered 44×44px top-right arrow; balance hero height (~125px) against grid cards (~170px) to prevent cavernous voids; use multi-row defensive telemetry to stop text collisions; Zero-Scroll applies only to compact decks, while rich-content views (Reading, Writing, Lexicon, Cockpit) scroll naturally (`overflow-y: auto`); all views must pass the iPhone 6 (375×667px) resilience standard with zero horizontal overflow and flawless clearance.
- Badge & Pill Anti-Wrap: pills, chips, and badges (`.skill-badge-pill`, `.hud-badge`, `.hud-pill`) strictly declare `white-space: nowrap; flex-shrink: 0; border: none;` using Apple-calm subtle background shifts to eliminate concentric double borders inside cards.
- Defensive Assessment Telemetry (No `undefined` / `NaN%`): all scorecard and exam receipt engines must defensively calculate finite numerical defaults from `rawScore` when detailed sub-scores or passage breakdowns are omitted. Never expose raw `undefined` or `NaN%` in UI receipts.
- Modal Language & Button Consistency: maintain 100% language consistency across modal cards (e.g. `Close Score Report` for Cambridge tests, `Đóng báo cáo kết quả` for Vietnamese; never a lone `Đóng`); primary actions must declare clean semantic styling without disruptive programmatic focus rings.
- Universal Button Border-Radius (`--radius-btn: 10px`): every single interactive button across the application (short chips like `B2`, medium buttons, full-width CTAs like `Flip Reveal` and `Evaluate Reconstruction`) must share the exact same radius token: `border-radius: var(--radius-btn, 10px);`. Button width or length does not dictate radius. Circle icon buttons (`border-radius: 50%`) are the only exception.
- Focus-Ring & Outline Clearance: coaxial focus rings (`outline: 2px solid; outline-offset: 2px; box-shadow: 0 0 0 2px var(--focus-ring-outer);`) must never collide with adjacent UI. Vertical button stacks use `gap: 12px !important;` (`.action-stack`, `.modal-actions`) ensuring ≥8px buffer from outlines. Action stacks maintain `margin-top: 18px`–`22px` from preceding text descenders/cards. Mobile action strips (like `quiz-footer-strip`) collapse to `column-reverse` with 44px touch floor on narrow screens (≤768px).
- Button Icon Padding & Spacing Invariant: every button containing an icon MUST declare inline-flex with vertical and horizontal centering (`display: inline-flex !important; align-items: center !important; justify-content: center !important; gap: 8px !important;`). Never use ad-hoc `margin-left` or `margin-right` on text spans; `gap` controls icon-to-text distance. Padding must be symmetrically balanced (`padding: 10px 16px` or `8px 18px`), keeping icon distance from the left edge equal to text distance from the right edge. Icons must declare `flex-shrink: 0; display: block;` so they lock onto the vertical center axis of font descenders without baseline sag. Step/roadmap rows must use structured flex cards (`align-items: center; justify-content: space-between;`) with `flex-shrink: 0; align-self: center !important;` on action buttons, preventing buttons from wrapping onto arbitrary second lines.
- File Explorer Folder Tabs & Uniform Grid Invariant: tab headers across multi-tab widgets/cards MUST declare an exact uniform grid distribution (`grid-template-columns: repeat(N, 1fr); width: 100%;` / Android `layout_weight="1"`) so each tab has an identical width (e.g. 25.0% for 4 tabs), preventing active tab pills from distorting unevenly across states. Tabs use folder index shoulders (`border-radius: 8px 8px 0 0`), with the active tab seamlessly sharing the folder body tone (`#182030`), top accent indicator (`box-shadow: inset 0 2.5px 0 0 #a5b4fc;`), zero bottom divider (`margin-bottom: -1px; z-index: 3`), and recessed inactive tabs (`#11151f`). Tab labels pair 1 emoji with 1 concise noun (`📖 Word`, `🧠 Quiz`, `🎯 Quests`, `⚡ Pillars`).

## IELTS app rules
- IELTS is a separate app side (`web/ielts.html`, `web/src/ielts/`), Academic only.
- Listening uses browser text-to-speech only.
- All scoring is computed locally by our own code. No external API, no LLM calls, no new dependency.
- Claude verifies every answer key; each question carries a `why` with the evidence line.
